# Changelog

All notable changes to this package are recorded here.

## 0.1.0 — 2026-09-25

First increment of a general-purpose package (design §3.1: many hosts, of which a Next/Supabase/Vercel host was the first), built to reach that host's UAT against the design and build plan (revision 4.2). Every module below is ESM only, has zero runtime dependencies, and never touches the DOM, network or filesystem at import time.

- **`core`** (`@papergiant/feedback` root, and `/core`) — the `feedback/v1` schema: `validatePayload()` (unknown-field rejection so a browser can never supply a server-derived field; NFC normalisation; control-character and lone-surrogate rejection; every field cap in `LIMITS`; an unrecognised `area` silently normalises to `'unknown'` rather than erroring), `neutralise()` and `fence()` (defang `@mentions`, issue references and URL separators; a fence sequence always longer than any run already in the text), and `renderTicket()` (the server-only title/source-hint/build-skew fields, a body ceiling enforced via `FeedbackTicketTooLargeError`, absent optional values omitted rather than rendered `null`). `KINDS` and `LIMITS` are exported as the single source of truth a host's own dialog UI can build against.
- **`build`** — `buildFacts()` (commit from the first present of `VERCEL_GIT_COMMIT_SHA`/`GIT_COMMIT_SHA`/`SOURCE_COMMIT` or a caller-supplied list, validated as 40 hex; a `YYYY.MM.DD-<7 hex>` release unless `FEEDBACK_RELEASE` overrides it; throws when `production` is true and no commit is known) and `releaseLabel()`.
- **`limit`** — the `Limiter` interface (fail-closed: a throw always means refuse); `memoryLimiter()` (synchronous-before-first-await counting so back-to-back calls can't overshoot either window, bounded subject tracking that never evicts a live subject); `rpcLimiter()` (adapts any `(subject) => Promise<unknown>` resolving a strict boolean, built to unwrap Supabase's `{ data, error }` shape in the caller's own callback); and `sql/postgres-limiter.sql`, a server-only-role Postgres function (`feedback_rate_take`) with a transaction-scoped advisory lock and a role placeholder each host replaces — plus a privilege-hardening revoke that ships **commented out** in the file and is REQUIRED on Supabase, where a host must uncomment (or otherwise add) it explicitly, since Supabase's own default privileges grant execution to `anon`/`authenticated` independently of the file's `revoke … from public`.
- **`github`** — `parsePrivateKey()` (PEM PKCS#1/PKCS#8, or base64 of either); `githubAppAuth()` (RS256 JWT signing, installation-token minting narrowed to one repository with `issues: write`, cached with a five-minute refresh margin, single-flight concurrent minting, `invalidate()` on a `401`); `tokenAuth()` (the fine-grained PAT fallback); and `githubSink()`, which maps every delivery outcome to the design's *received*/*not sent*/*delivery unconfirmed* three-way split (definitive refusals for `400/401/403/404/410/422/429`; inconclusive for `5xx`, network errors, the ten-second timeout, and an unparseable `201`), compares requested versus returned labels and logs `FEEDBACK_LABELS_DROPPED` (a count only) when GitHub silently drops one, and never follows a redirect on either the mint or the issue-create request. Every credential failure is a `FeedbackCredentialError` with a fixed, static message — never key material or a response body.
- **`server`** — `createFeedbackHandler()`, a framework-free `(Request) => Promise<Response>`: method, credential-header, media-type, origin and `Sec-Fetch-Site` checks; a streamed 32 KiB body cap; `identify()` then the limiter, in that order, so a refused identity never spends quota; validation and rendering; delivery. Every log event carries ids and codes only — reporter text, the rendered ticket and identity references never reach `log()`.
- **`browser`** — `mountFeedback()`: an open shadow root around a native `<dialog>`, a constructable stylesheet themed with `--feedback-*` custom properties, the Help/Bug/Idea form with a live "Details included" disclosure, and the three delivery states (kept draft and reused `report_id` on *unconfirmed*, with a shown duplicate-risk warning). Host-modal handling per the design: nests inside an open host modal that contains the launcher (Radix `Dialog`/`AlertDialog` and a `showModal()`-opened native dialog recognised by default), stopping Escape at the window capture phase and wheel/touch propagation at the host element without preventing their default, both removed on close and destroy; refuses when the launcher is outside the modal or nesting would go more than one level deep. Requests are sent `credentials: 'same-origin'`, `referrerPolicy: 'no-referrer'` so the page's own path and query never leak in a `Referer` header. `mountLauncher()` adds an optional fixed side-tab trigger.
- **`react`** — `<FeedbackProvider>` (mounts/recreates on an explicit, primitive dependency list — never a whole-object `JSON.stringify` — and a separate `enabled` flag that degrades every consumer safely instead of throwing), `useFeedback()`, `<FeedbackButton>` (always `type="button"`, honours a caller's `preventDefault()` as a veto, passes its own element so nesting needs no host code), and `<FeedbackArea>` (a mount-order stack so "most recently mounted wins" is well-defined even across sibling layouts — one `<FeedbackArea>` per page, never in a layout, is the supported pattern). Tested under React 19 in this package, and under React 18 by an independently installed consumer (`examples/react18`) that installs the packed tarball, typechecks with `skipLibCheck: false`, server-renders, and runs in three browser engines.
- **`doctor`** (bin `papergiant-feedback`, run as `npx @papergiant/feedback doctor`) — a read-only installation checker across nine checks: environment names present; the private key parses; an installation token mints narrowed to the intake repository with `issues: write`; the repository has issues enabled (and warns if it isn't private); every configured label exists; every configured origin is a bare origin and includes the app URL's own; and, given `--production` and `--limiter memory|shared` (with `--single-instance` for a genuinely single-instance host), whether the configured limiter is safe for production — doctor never infers the limiter kind on its own. Every setting has a matching flag and environment-variable default (`--dotenv-file` reads non-secret defaults from a dotenv-style file, parsed as data and never executed; the private key has no flag, by design). `doctor --help` documents every flag and exit code.
- **Docs and publishing**: `INSTALL.md` (prerequisites, one-time per-client GitHub set-up, a recipe per host type, the limiter SQL install steps, `doctor`, troubleshooting, and an `AGENTS.md` block); a tagged-release `publish.yml` using npm trusted publishing (OIDC, `--provenance`) behind a required-reviewer `npm` environment, plus a `workflow_dispatch` dry-run.
- **Testing**: golden-ticket and hostile-input tests for the renderer; unit tests for every module above; a Postgres service-container suite for the limiter SQL, including concurrency at both rate-limit boundaries; a real-browser Playwright matrix (delivery states, the collection boundary, accessibility, host-modal nesting) against an `examples/fixture` Hono host with a controllable stub GitHub. CI packs the package and installs the tarball into the fixture, `examples/react18` and a no-React `examples/vanilla` (which proves every entry except `/react` works with no React installed), and runs each consumer's suite on Chromium, WebKit and Firefox. Every TypeScript and JavaScript sample in INSTALL.md and README.md is typechecked in `examples/docs-check` against real Next, React, Supabase, Hono and Vite.
